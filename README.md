# esp32-joystick2trainer

[![CI](https://github.com/RobertoD91/esp32-joystick2trainer/actions/workflows/ci.yml/badge.svg)](https://github.com/RobertoD91/esp32-joystick2trainer/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

Firmware for the **ESP32-S3** that turns a wired **USB HID joystick** into a trainer input for
**EdgeTX** radios such as the **RadioMaster TX16S MKII**. The ESP32-S3 acts as a native USB host,
decodes the joystick's HID reports and emits **SBUS** and **CPPM** at the same time on two GPIOs.

```text
USB HID joystick  (e.g. Microsoft SideWinder Force Feedback 2, 045E:001B)
      │  USB full speed
      ▼
ESP32-S3 native USB host  ──►  HID report descriptor parser  ──►  normalised axes/buttons/hat
      │
      ▼
configurable channel mapping (source, invert, dead band, expo, end points, trim, failsafe)
      ├──►  SBUS  (UART1, 100000 8E2, hardware inverted)  ──►  GPIO 17
      └──►  CPPM  (RMT peripheral, no bit-banging)        ──►  GPIO 18
```

Force feedback is intentionally out of scope for now: the SideWinder's PID (physical interface
device) reports are ignored, only its joystick input report is used.

> **Status:** the code builds, the hardware independent parts are covered by unit tests run in CI,
> and the USB/RMT/UART layers follow Espressif's reference patterns. It has **not yet been
> validated on a physical TX16S MKII**; feedback from the first users is very welcome.

## Features

- **Native USB host** on the ESP32-S3 (ESP-IDF `usb` host library + Espressif `usb_host_hid`
  class driver). No Bluetooth, no external USB host shield.
- **Generic HID joystick support**: the report descriptor is parsed at run time, so any joystick
  or gamepad that follows the HID usage tables works (X/Y/Z/Rx/Ry/Rz/slider/dial/wheel,
  throttle/rudder/accelerator/brake, hat switch, up to 32 buttons, report IDs, array buttons).
  The SideWinder Force Feedback 2 descriptor is part of the test suite.
- **SBUS and CPPM simultaneously**, each on its own GPIO, each individually configurable
  (period, polarity, number of channels, pulse width, frame length).
- **CPPM generated by the RMT peripheral**: the whole frame is handed to the hardware, timing does
  not depend on interrupt latency or on the USB task.
- **SBUS inversion in hardware** (UART TX inverter of the ESP32): no external transistor.
- **Safe disconnection handling**: on USB unplug the outputs go to a configurable failsafe
  (stop, hold, preset). By default they simply stop, which makes EdgeTX hand control back to
  the instructor's sticks within one second.
- **Everything configurable at run time** from a serial console and persisted in NVS:
  GPIOs, mapping per channel, inversion, dead band, expo, end points, trims, failsafe values,
  timings. Compile-time defaults are `-D` flags in `platformio.ini`.
- **PlatformIO project** with host-side unit tests (`pio test -e native`) and a GitHub Actions
  pipeline (format check, tests, firmware build with downloadable artifacts).

## Hardware

### Bill of materials

| Item | Notes |
|------|-------|
| ESP32-S3 dev board | Tested build target: `esp32-s3-devkitc-1`. Any ESP32-S3 board that exposes the **native USB** pins (GPIO19/20) works. |
| USB OTG cable **with power input** | Micro-USB (USB-C on some boards) OTG host plug + USB-A female for the joystick + a power input. See [Powering the joystick](#powering-the-joystick): a plain OTG adapter is not enough on the DevKitC-1. |
| USB-to-UART link | The DevKitC-1's second connector labelled "UART"; used for flashing, logs and the configuration console. |
| 3.5 mm TRS plug | For the CPPM trainer input of the radio. |
| Dupont wires / JR pins | For the SBUS input (module bay S.PORT pin or AUX serial connector). |

### Powering the joystick

The joystick must receive **5 V on VBUS** from the host connector, and the
**ESP32-S3-DevKitC-1 cannot provide it by design**: in the board schematic the VBUS pin of the
native "USB" connector (J4) reaches the 5 V rail only through the Schottky diode D7, oriented
from the connector *into* the board. The board can be powered from that port, but 5 V never
flows out to a connected device, and there is no jumper or solder pad to change that. The
firmware therefore enumerates nothing until VBUS is supplied in one of these ways:

1. **OTG Y-cable with power input** (no soldering, recommended): a "micro-USB OTG host + power"
   cable. Its power socket takes 5 V from a USB charger, its USB-A socket feeds the joystick, and
   the same 5 V also enters the board through D7, so one supply powers everything while the
   UART port stays free for the console.
2. **Wire from the header pin `5V` to the VBUS pad of J4**, or a solder bridge across D7. The
   board is then powered from the UART port or the `5V` pin. With D7 bridged, never connect a
   PC to the native port while the board is powered from another source.
3. **USB-A female breakout on the header**: VBUS to `5V`, GND to `GND`, D+ to `GPIO20`, D- to
   `GPIO19`, short twisted wires; the on-board connector is left unused.

The SideWinder FFB2 declares 100 mA over USB; it also has its own mains power supply for the
motors, which must be connected for the stick to enumerate reliably.

Power the ESP32 from its UART/USB connector or from a clean 5 V source. **Do not** power it from
the radio's module bay `BATT` pin: that pin carries the battery voltage (up to 8.4 V).

### GPIO usage (defaults)

| Signal | GPIO | Level | Change with |
|--------|------|-------|-------------|
| SBUS out | 17 | 3.3 V, idle low (inverted UART, standard SBUS) | `set sbus.gpio N`, `set sbus.inverted 0/1` |
| CPPM out | 18 | 3.3 V, idle high, 300 µs low pulses | `set cppm.gpio N`, `set cppm.inverted 0/1` |
| Status LED | none (-1) | active high | `set led.gpio N` |
| USB host D-/D+ | 19 / 20 | native USB | fixed |
| Console | UART0 (USB-UART bridge) | 115200 8N1 | fixed |

Avoid the strapping pins (0, 3, 45, 46), the flash/PSRAM pins (26-37 on modules with octal
PSRAM) and 19/20 (USB). 3.3 V logic is enough for the STM32 inputs of the TX16S (they are 5 V
tolerant, threshold about 2 V).

## Wiring to the TX16S MKII

EdgeTX offers several trainer input modes. The ones usable with this bridge on a TX16S are:

| EdgeTX trainer mode | Physical input on the TX16S | Signal to send | Bridge setting |
|---------------------|-----------------------------|----------------|----------------|
| **Master/Jack** | 3.5 mm trainer jack on the back | CPPM | `cppm.*` defaults |
| **Master/SBUS Module** | external module bay, **S.PORT** pin (with External RF **off**) | SBUS, standard polarity (idle low) | `sbus.inverted 1` (default) |
| **Master/Serial** | AUX1 (or AUX2) serial port configured as "SBUS Trainer" | SBUS, **UART polarity** (idle high) | `sbus.inverted 0` |
| Master/CPPM Module | module bay HEARTBEAT pin | – | **does not work on the TX16S/MKII** (hardware issue, EdgeTX issue #4672) |

EdgeTX uses one trainer mode per model, so in practice you connect **either** the CPPM output
**or** the SBUS output to the radio. Both are generated all the time; the other one is free for a
second radio or a simulator dongle.

### CPPM on the trainer jack (recommended, simplest)

```text
ESP32-S3 GPIO18 ──────► tip    (PPM)      3.5 mm TRS plug
ESP32-S3 GND    ──────► sleeve (GND)
                        ring   not connected
```

This follows the OpenTX/EdgeTX convention (PPM on the tip, ground on the sleeve, ring unused).
The original TX16S used a 4-pole socket, the MKII a standard 3-pole TRS socket. If your radio
does not see the signal, verify the socket with a multimeter (sleeve = ground) before assuming
a firmware problem. EdgeTX measures rising edge to rising edge, accepts 800-2200 µs per channel
and needs a sync gap of 4-19 ms; the encoder keeps every frame inside that window by design.

### SBUS on the module bay (S.PORT pin)

```text
JR module bay (top to bottom):  1 PPM   2 HEARTBEAT   3 BATT   4 GND   5 S.PORT
ESP32-S3 GPIO17 ──────► pin 5 (S.PORT)
ESP32-S3 GND    ──────► pin 4 (GND)
```

Keep `sbus.inverted = 1` (standard SBUS). Set the model's External RF to **OFF** or the mode is
not offered. Never connect pin 3 (BATT) to the ESP32.

### SBUS on the AUX serial port

Set `sbus.inverted = 0` (the STM32F4 in the TX16S cannot invert its UART input) and connect the
bridge's SBUS GPIO to the AUX RX pin and ground to ground. Do not exceed 3.3 V on the AUX pins.
See [docs/edgetx-tx16s.md](docs/edgetx-tx16s.md) for the EdgeTX serial-port settings.

## EdgeTX setup

1. **Radio Settings → Hardware** (only for the AUX variant): Serial ports → AUX1 → `SBUS Trainer`.
2. **Model Settings → Trainer → Mode**: `Master/Jack` (CPPM), `Master/SBUS Module` or
   `Master/Serial`.
3. **Radio Settings → Trainer**: for each stick choose the mode (`Add` or `Replace`), the source
   channel (`CH1`…) and the weight. With the bridge connected and the joystick centred press
   **Cal** so that 1500 µs (SBUS 992) is the centre. Full travel is ±500 µs (SBUS 172…1811).
4. **Special Function**: add `Trainer` on a switch (for example `SH↓`) to enable stick takeover
   with that switch. When the switch is off, or when the trainer signal disappears, the radio's
   own sticks are used.
5. The trainer channels are also available as sources `TR1…TR16` in Inputs and Mixes, useful for
   buttons and the hat switch (default channels 5-14).

Default channel order (AETR + buttons), see [docs/configuration.md](docs/configuration.md):

| Channel | Source | Notes |
|---------|--------|-------|
| 1 | X (aileron) | |
| 2 | Y (elevator), inverted | forward = high |
| 3 | Slider (throttle), inverted | lever forward = high; failsafe = 1000 µs |
| 4 | Rz (twist, rudder) | |
| 5, 6 | buttons 1, 2 | trigger, thumb |
| 7, 8 | hat left/right, hat up/down | |
| 9-14 | buttons 3-8 | |
| 15, 16 | unassigned | 1500 µs |

## Building, flashing, testing

Requirements: [PlatformIO Core](https://docs.platformio.org/en/latest/core/installation/index.html)
(`pip install platformio`). The first build downloads the ESP-IDF 6.x toolchain (about 1.5 GB)
and the `espressif/usb` + `espressif/usb_host_hid` components from the ESP component registry.

```bash
pio run -e esp32s3                       # build the firmware
pio run -e esp32s3 -t upload             # flash through the UART connector
pio device monitor -b 115200             # logs + configuration console
pio test -e native                       # hardware independent unit tests (host)
```

CI builds every push and publishes `firmware.bin`, `bootloader.bin` and `partitions.bin` as a
workflow artifact; they can be flashed with `esptool.py` (offsets 0x0, 0x8000, 0x10000).

### Flash from the browser

No toolchain needed: open **https://robertodisanto.it/esp32-joystick2trainer/** in Chrome or
Edge, connect the board's UART port and click *Connect* (the page must be loaded over HTTPS,
Web Serial is not available on plain HTTP). The page (source in `web/`) is
redeployed by CI from `main` only after the format check, the unit tests and the firmware build
have passed, so it always serves a firmware that went through the whole pipeline.

## Configuration

Open the console (`pio device monitor` or any terminal at 115200 baud on the UART port) and type
`help`. The main commands:

| Command | Description |
|---------|-------------|
| `status` | joystick, outputs, current channel values |
| `hid` | parsed report descriptor and axis bindings of the connected joystick |
| `monitor [s]` | live axes/buttons/channels for a few seconds |
| `show [prefix]` | all configuration keys, or those starting with a prefix (`show ch3.`) |
| `set <key> <value>` | change a key in RAM |
| `save` / `load` / `defaults` | persist to NVS / reload / factory reset |
| `reboot` | restart (needed after changing GPIOs or enabling/disabling an output) |

Examples:

```text
set ch4.src axis:rz        # channel 4 follows the twist axis
set ch4.invert 1
set ch4.deadband 5         # 5 % dead band around the centre
set ch3.src axis:slider
set ch3.expo 30
set ch9.src btn:3
set ch9.toggle 1           # button 3 toggles channel 9
set cppm.channels 8
set sbus.inverted 0        # SBUS for the AUX port (UART polarity)
set failsafe.mode stop
save
```

The complete key reference is in [docs/configuration.md](docs/configuration.md).

## Architecture

```text
lib/rc_core     pure C++17, no hardware:  SBUS encoder, CPPM waveform encoder, RMT symbol
                packer, channel mapper, configuration model + key/value interface
lib/hid_core    pure C++17, no hardware:  HID report descriptor parser, joystick decoder
src/app         ESP-IDF layer:            UsbJoystick (usb host + hid driver), InputHub,
                                          SbusOutput (UART), CppmOutput (RMT), ConfigStore (NVS),
                                          console (esp_console), StatusLed
src/main.cpp    wiring of the above
test/           Unity tests for lib/ (run on the host, `pio test -e native`)
```

Tasks at run time:

| Task | Core | Role |
|------|------|------|
| `usb_lib` | 0 | USB host library daemon |
| HID driver task | 0 | USB transfers, calls back with raw reports |
| `hid_evt` | 0 | opens new devices, fetches/parses the report descriptor |
| `sbus` | 1 | one frame every `sbus.period` µs (esp_timer driven) |
| `cppm` | 1 | keeps two frames queued in the RMT hardware |
| console REPL | any | configuration commands |

Decoded reports are mapped to channels on the USB task and stored in the `InputHub`; the output
tasks only read the latest frame and apply the failsafe policy. Disconnection is detected by the
USB host stack (port disconnect), not by a data timeout, because many joysticks only send a
report when something changes. An optional data timeout exists (`input.timeout`) for devices
known to stream continuously.

## Design decisions

The full evaluation of the existing projects is in [docs/research.md](docs/research.md). In short:

- **ESP-IDF instead of Arduino.** The official PlatformIO `espressif32` platform ships Arduino
  core 2.x (IDF 4.4) for the S3, which lacks the current USB host stack; the community
  `pioarduino` platform fixes that but adds an unofficial dependency. Pure ESP-IDF 6.x gives the
  USB host library, the `usb_host_hid` class driver, the RMT TX driver, UART inversion,
  `esp_console` and NVS directly, with the official PlatformIO platform.
- **Espressif's `usb_host_hid` driver, pulled from the component registry**, instead of copying
  it into the tree (as `esp32beans/ESP32_USB_Host_HID` does) or using `EspUsbHost` (Arduino-only,
  very large, unstable API).
- **Own HID descriptor parser and joystick decoder** (about 500 lines, allocation-free, unit
  tested with the real SideWinder descriptor) instead of per-device hard-coded report layouts
  keyed on report length, which is what every ESP32 joystick example found does.
- **Own SBUS and CPPM encoders**: they are tiny, they must be testable on the host, and the
  Arduino-oriented libraries (`bolderflight/sbus`, `DiyMotionController`) would only add a
  `Serial`/timer-ISR dependency. CPPM on the RMT peripheral is unique to this project; every
  other ESP32 implementation uses a timer interrupt and `digitalWrite`.
- **Nothing reused from `USB_to_RC`** (RP2040 + PIO USB, GPL-3.0) beyond its architecture idea of
  descriptor-driven parsing plus a mapping layer.

## Limitations and roadmap

- No force feedback (PID output reports are not sent). The SideWinder's centring spring is
  therefore inactive; the axes still report normally.
- One joystick at a time (the first HID interface with joystick usages wins).
- Not yet validated on real hardware; the first item on the roadmap is a bench test with a
  TX16S MKII (jack + S.PORT) and a logic analyser capture of both outputs.
- Possible extensions: per-device profiles keyed on VID/PID, a Web/USB configuration UI, CRSF
  output, multiple joysticks merged into one frame.
